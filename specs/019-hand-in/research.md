# Research: The hand-in (019)

Decisions taken while planning, each with the reason and what else was considered. The facts
were checked on 16 Nov 2026 against the generated files in `docs/report/` and the code.

## R1. Where the slides are made

- **Decision**: the slides are made as a claude.ai Slides artifact (private by default), shown
  in a browser, and downloaded as PDF and PowerPoint the day before each presentation as the offline
  copy and the hand-in file. After the final presentation, the PDF may be committed to
  `docs/presentation/` (aggregates only, FR-003).
- **Rationale**: a live preview the researcher can page through and comment on, 16:9 layout, and
  a download in both common formats (FR-006), with no new dependency in the repository.
- **Alternatives**: a PowerPoint file generated by a script in the repository (reproducible, but
  slower to design and no preview); HTML slides in the repository (needs hosting or a local
  server on the day); Google Slides (outside the tools at hand).

## R2. Where the slides' numbers come from

- **Decision**: a generated number sheet, `docs/presentation/numbers.md`, written by
  `python -m sentinel.presentation`. It reads `docs/report/model_card.json` (the one-time test's
  results and band records, and the test years' results, for the three models), the catching-up
  report and the data audit (their generated tables), and a few counts from the serving copy
  (read-only). Each number gets an id, its value as shown on a slide, its source and its meaning.
  The slides, the speaker notes, the README and the demo take numbers from this sheet only.
- **Rationale**: SC-002 asks for exact numbers; copying from a generated sheet by id is checkable,
  and the project's rule is that reports are generated by commands, never edited by hand.
- **Alternatives**: typing the numbers into the slides from the model report (typing errors, no
  check); a hand-written sheet checked by a script (two places to keep in step).
- **Facts checked**: the model card's `holdout` entry exists for all three models with
  `results` and `bands` per year and over all. Dilution: 148,067 company-months, forecasts made
  at month-ends from 2023-01-31 to 2026-04-30. The dilution model's log loss is 0.2292 against
  0.2556 (logistic), 0.3112 (rule) and 0.3693 (base rate), with an AUC of 0.9075. The results-day
  move model's mean log loss is 0.4672 against 0.4517 for the ridge. The volatility model's mean
  absolute log error is 0.2522 against 0.2529 for the ridge, and its 80% range covered 81.5%.

## R3. The app shows the one-time test (FR-009)

- **Decision**: the app's model section (diagnostics) adds two tables read from the model card's
  `holdout` entry: log loss per level and year from 2023 on, and the bands' forecast against
  the share that diluted over all years from 2023 on. Today the section shows only the test years
  (2019-2022) and the sentence "The one-time test on 2023+ data has been run (see the model
  report)".
- **Rationale**: the demo can then show the final numbers inside the product, and the band record
  a visitor sees includes data the model never saw (D62: chances with their past hit rates).
- **Alternatives**: leave the app as it is and show the numbers only on slides (the demo would
  show older evidence than the talk).

## R4. The demo path

- **Decision**: 5-6 steps chosen by role, not by name: today's highest risks, one high-risk
  company in depth, a large company's insiders and filings, a company left out by a rule, a price
  history kept across a ticker change, the model section. The companies are picked on the data of
  16 Nov from the named cases where possible (they are checked by `python -m
  sentinel.web.named_cases`), each with a spare. The written path (`demo.md` in this folder)
  says what to point at, never an exact chance, since the data change daily.
- **Rationale**: steps that do not depend on today's numbers survive the days between rehearsal
  and presentation; the named-case check proves the pages show the data.
- **Candidates** (to confirm on the data, task T00x): high risk, the landing page's top companies;
  large company, Apple; left out by a rule, PDS Biotechnology or Hyperscale Data (a price below
  $1); ticker change, MGP Ingredients (MGPI to CASK on 5 Nov 2026) or Viavi (JDSU to VIAV).

## R5. The demo's backup (FR-010)

- **Decision**: screenshots of each step taken with Chrome on Windows in headless mode against the
  local app, stored in `data/handin/backup/` (git-ignored, this computer only). If the password
  cannot be passed to a headless browser, a second instance without a password is started on
  127.0.0.1 for the few minutes the screenshots take, then stopped.
- **Rationale**: the app's price charts use the private price source, so the backup may never
  leave this computer; Chrome and Edge are already installed on Windows, so nothing new is
  installed.
- **Alternatives**: a screen recording (larger, the same privacy limits); screenshots by the
  researcher during the rehearsal (kept as the fallback).

## R6. The README's front page (FR-012, FR-013)

- **Decision**: the README opens with, in order: what the project answers (the dilution chance
  for any US stock, plus facts, insiders, filings and short selling); the one-time test's results
  (a small table for the dilution levels, one line each for the other two questions); the app
  (what it shows, local only, how to start it); how it works (sources, six layers, the daily
  update); the rules; installation and the main commands; a map of the folders; the limits. The
  current sections (roadmap, working together, notes for agents, daily use, notebooks, model
  report, holdout test) follow under "Working notes". A unit test checks that the README's results
  table equals the model card's numbers as rounded there.
- **Rationale**: a grader reads the first screen first; the test keeps the hand-written page in
  step with the generated card, in CI as well.
- **Alternatives**: a README generated by a command (heavy for one table); no check (the table
  could drift from the report).
- **No screenshots** in the public README: a page of the app shows prices from the private source.

## R7. The fresh-copy check (FR-014)

- **Decision**: clone the public repository into the scratchpad, install by the README's own
  instructions (`uv sync`), run the unit tests and the lint and format checks without `data/`.
- **Rationale**: SC-004; CI already does the same on every pull request, so this mostly checks the
  README's instructions.

## R8. The old app (FR-015)

- **Decision**: removed in this feature only once the researcher approves the new app (026 T021):
  `src/sentinel/app/`, its tests, its Docker files and the `sentinel serve` command. Its spec-kit
  folder (`specs/011-app-design/`) stays as history. Until then the README says it is replaced.
- **Rationale**: in a public repository it is the code a grader could run that shows invented data
  when the serving copy is missing (the audit of 4 Nov).

## R9. Timing

- **Decision**: about 8.5 minutes of slides (10 slides with title and close), 5 minutes of demo, a
  minute spare; the speaker notes are written at about 130 words a minute (about 1,100 words).
- **Rationale**: SC-001 asks for 14 minutes or less in rehearsal; the switch from slides to the app
  and back takes about 20 seconds.

## R10. The daily update during a presentation

- **Decision**: no change to the schedule. The update (weekdays from 10:00, about 50 minutes)
  replaces the serving copy only when complete, and the app re-reads it when the file changes, so
  the app keeps serving. If the presentation falls in that hour, the presenter opens the app a
  few minutes before and checks the data date.
