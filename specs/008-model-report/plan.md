# Implementation Plan: Model report and model card data

**Branch**: `008-model-report` | **Date**: 2026-11-09 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/008-model-report/spec.md`

## Summary

Replace Gemini's `sentinel report` (typed-in numbers) with a report generated from records the
three approved model notebooks write. Each notebook gets a last code cell that records its tables
(data, folds, every level × test year, the choice, the bands, the calibration or range coverage,
the hypotheses, the frozen model) as one JSON artifact in an MLflow run named `report`, through one
shared function (research R1). The three notebooks are re-run once on the same export (R2).
`sentinel report` reads the newest non-trial record per question (R3) and writes
`docs/report/model_report.md` with its figures and `docs/report/model_card.json` for the app (R4,
R6); it fits nothing and is deterministic. The holdout section shows 010's records unedited when
they exist (contracts/report-record.md).

## Technical Context

**Language/Version**: Python 3.14 (uv)

**Primary Dependencies**: MLflow (records), pandas, matplotlib (figures, Agg backend), PyYAML
(the definitions from `config/risk_params.yaml`); no new dependency (Markdown tables rendered by
the module).

**Storage**: reads `data/mlflow.db` and its artifacts; writes `docs/report/` (committed).

**Testing**: pytest on a temporary MLflow store with synthetic records (research R7).

**Target Platform**: the researcher's WSL machine; any clone with the data.

**Project Type**: a module and a command in the existing package, plus a recording cell in three
notebooks.

**Performance Goals**: the command in under a minute (SC-004); the notebook re-runs about 45
minutes in all, once.

**Constraints**: no typed-in number (FR-001); aggregates only (FR-005); deterministic output
(FR-006); notebooks committed without outputs.

**Scale/Scope**: three questions; one Markdown report, a few figures, one JSON.
